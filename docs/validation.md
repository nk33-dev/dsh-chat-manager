# 验证记录

## 0.2.5

2026-11-08。Windows 11，Node 24.16.0，Harness `0.2.2-rc.1`。

### 自动检查

`pnpm check` 通过，`pnpm test` 51 项通过，`verify-client.mjs` 通过（只引用白名单模块，注册 6 个槽位），`pack:plugin` 通过。

本版补了四组测试：确认框从行内搬走后仍存活、工作区删除的四种结局、`workspaceRegistry.delete` 包装可还原、宿主晚注册字典时仍能改写文案。

### 真实 Harness

CDP 实测，逐项确认：

- 行内垃圾桶用真实鼠标事件点击，确认框稳定停留（4.5 秒以上无消失），标题带会话名。
- 删除工作区：注册从 `workspace.json` 与 `workspaceIds` 中都移除，目录保留。
- 工作区删除确认框的说明已替换为「将把「X」和里面的会话一起删除。会话会移到回收站，可以恢复。」
- 回收站页「会话」标签的计数胶囊有数字。

### 未验证

- **删工作区时把会话移进回收站这条路径，只有单元测试覆盖。** 真实环境里没跑过——需要给工作区挂一个可牺牲的会话，测完还要回滚，风险高于当时愿意承担的程度。
- 撤销工作区删除（重建注册并把会话放回原位）同样只有单元测试。
- 子代理会话（`origin: "subagent"`）没单独处理。
- 回收站与 Harness 并发写 `workspace.json` 没测，没有乐观锁。
- Harness 持有文件句柄时删除没测，`rename` 失败走 copy+unlink 兜底，没实际触发过。
- 超过 200 个会话的工作区没测分批逻辑。
- 多 profile 切换没测。

### 已知限制

- 提示条只保留一条，连续删两次前一次被覆盖。
- 彻底删除直接删条目目录，确认框之外没有额外保护。
- 接管 `workspaceRegistry.delete` 依赖宿主在调用时读取该方法，而不是构造时绑定。宿主改成绑定时接管会静默失效。
